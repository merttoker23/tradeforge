Tradeforge bounded production diagnostics: administrator installation instructions

These are reviewable instructions, not evidence of installation. No production
commands, sudo, Docker, private exchange calls, grants or role creation were run
to develop this helper. The helper itself never changes permissions or data.

Scope and trust
  Install production_diagnostics.py as exactly the single root-owned file below.
  It imports only system stdlib with /usr/bin/python3 -I, imports no sibling/app
  code and accepts zero arguments. Do not run it using a caller-selected Python.
  All parent directories /usr, /usr/local and /usr/local/sbin must be root-owned,
  non-symlink directories, with no group/other write permissions. The installed
  helper must be root:root 0755, regular, single-link and not a symlink. Verify
  the system Python and Docker binaries are administrator-managed as usual.
  The helper ignores caller environment, uses cwd=/, disables stdin, uses fixed
  absolute binaries and never executes a shell. Docker target IDs are validated
  against project=forgetrade, working_dir=/opt/forgetrade and service allowlists.
  It only performs fixed ps/inspect/image inspect/logs operations and fixed
  per-service python -I -S -B localhost GETs or fixed local psql read-only SQL.

Output and limitations
  DB failures include only a fixed failure code and failed_section when known.
  Fixed SELECT markers identify the role gate or aggregate boundary; psql SQLSTATE
  verbosity never returns raw error text. DB_QUERY_CANCELED does not assume a
  timeout cause; DB_ROLE_POLICY_REJECTED is the least-privilege gate, not a request
  for broader grants. If a role was already installed, do not rerun access setup
  merely because status is UNKNOWN. Inspect the bounded failure code first.
  If an aggregate is canceled after the role gate, only the same fixed SELECTs
  are read separately, each with its own role gate and READ ONLY transaction.
  The nine pipeline counts use separate statements with the original predicates.
  Role checks and ordinary SELECTs keep1200ms. Only four production-measured
  canceled reads (opportunities, regimes_72h, history_72h, history_revisions_72h)
  receive a fixed10000ms statement limit AFTER their role gate. All300ms lock,
  12s process and90s global limits remain unchanged. This diagnostic read budget
  does not change an application, exchange, risk or authorization setting.
  No retry occurs after role/auth/policy rejection. Unavailable counts stay null;
  independently completed sections are OK, incomplete sections/snapshots PARTIAL.
  These independent snapshots have different transaction times; compare their
  timestamps and do not treat them as one atomic cross-service/72h observation.
  One JSON snapshot, at most 96 KB; process output reads are capped incrementally
  (including discarded stderr); each command has a <=12s deadline and the whole
  helper a 90s alarm. It prints explicit UNKNOWN/null on missing evidence. Exit 0
  means a snapshot was collected, not that services are ready or DB was readable.
  Per-service metadata: state, running, image ID/digest/revision, started time,
  restarts/OOM/health. Readiness and authenticated /market-state use only fixed
  localhost ports inside the correct container, no proxy, redirect or exchange
  call. The mounted gateway_token is read only inside that container, never sent
  to the host, caller or logs. App imports, Binance endpoints and private account
  queries are absent. App GET handlers may perform their existing internal DB
  reads; the helper never invokes exchange clients or mutation endpoints.
  Logs cover only 100 trailing lines in the last 15 minutes. Only structured,
  typed allowed fields and exact known reason codes survive; free text, exception
  strings, identifiers, symbol lists and unknown codes are discarded/redacted.
  A nonempty discarded count is expected for unstructured/unknown application logs.
  Database output distinguishes 72h transitions, unique decisions and latest
  candidate states; event counts, stage last times, pending/delivered outbox and
  current orders, regime samples/distinct source periods, canonical revisions
  and 5m/15m/1h stored interior gap counts. Retention can remove historical bars;
  these counts cannot prove full universe coverage or absence of edge-window gaps.
  Runtime observations are CURRENT GAUGES, not a 72h frequency/time series. Latest
  state/current tables can be older than 72h and are labeled separately.
  Unknown/new reason codes become UNKNOWN, never arbitrary token-shaped text.
  No account balances, order/client IDs, credentials, raw errors or raw logs appear.
  Concurrent service changes or individual failures can produce a partial snapshot.
  The helper itself is not installed and no administrator access is implied by
  the presence of these files in a user-owned review workspace.
